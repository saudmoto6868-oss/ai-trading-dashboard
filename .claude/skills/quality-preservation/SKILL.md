# Quality preservation

- Treat quality and safety as constraints, not budget variables.
- Preserve existing behavior unless the task explicitly requires a change.
- Never delete, weaken, bypass, or relabel required tests to save tokens.
- Use the narrowest relevant tests first, then required integration/regression checks.
- Report mock-only, static-only, and live validation distinctly.
- Keep work on the assigned branch; never push to main or another contributor's branch.
- Inspect existing hooks, settings, generated files, and contracts before changing them.
- Do not merge, deploy, run paid workflows, or perform financial actions without owner authorization.
- If budget is exhausted, checkpoint and stop rather than shipping an unverified shortcut.
