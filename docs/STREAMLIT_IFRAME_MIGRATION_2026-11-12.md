# Streamlit iframe API migration — 2026-11-12

The project pins Streamlit 1.66.0. The deprecated `components.html()` API was replaced with `st.iframe()` for JavaScript-based HTML documents in these application modules:

- `modules/workspace.py`
- `modules/header_bar.py`
- `modules/tv_widget.py`
- `modules/micro_foundations.py`
- `modules/quant_edgemap.py`
- `modules/quant_execution.py`
- `modules/quant_montecarlo.py`
- `modules/quant_robustness.py` (no longer: since 2026-11-20 it is a native Streamlit table of the real lab rows, no iframe)
- `modules/spot_page.py` (four embeds)
- `modules/tia_workspace.py`
- `modules/veles_robustness.py`
- `main.py` (QuantStats report)

The parallel V7 integration branch separately migrates the three embeds in `modules/v7_page.py` and verifies them in `tests/test_v7_live_wiring.py`.

These are JavaScript-based HTML documents, so an iframe is required. `st.html()` is not a drop-in replacement for the interactive pages. Fixed iframe heights are preserved and accessible descriptions are supplied. Streamlit 1.66.0 has no `scrolling` argument on `st.iframe`: the header and workspace documents set `html,body{overflow:hidden}`, the TradingView embed adds the same containment, and the other analytical pages remain scrollable by design.

The HTML is generated by trusted application code; no user-provided or LLM-generated HTML is passed to the iframe.

Regression-check scope: `tests/test_streamlit_iframe_migration.py` scans `main.py` and all Python files under `modules/` except `modules/v7_page.py` for both `components.html(` and `components.v1.html(`, checks the twelve expected iframe modules, verifies the fixed-height overflow behavior, and compiles each migrated Python module. `modules/v7_page.py` is separately migrated and guarded by the V7 integration branch. The scan does not cover scripts, tests, or non-Python files.
