## 3. Conflicts and inconsistencies found
1. **Risk (REAL CONFLICT).** The settings image has `DEFAULT_RISK_PERCENT 0.5`; the platform policy (!47, merged) is 0.25 % base, 0.50 % only for grade A+ with validation_n >= 30. CFX must call `modules/risk_policy.py`, never its own default.
2. **Minimum R:R (REAL CONFLICT).** CFX hard gate RR1 >= 1.5; the platform's rule is 1:2. The stricter one wins on the platform.
3. **Sessions (NOT a conflict, corrected).** I earlier counted several definitions. Converted (Cairo = NY + 7 h in November): the settings image's display sessions (Cairo 02-09 / 09-16 / 15-00) equal v7 `SESS_WINDOWS` (NY 19-02 / 02-09 / 08-17), and the kill zones (NY 20-00 / 02-05 / 07-10) match the platform's `TCE.nextSession` zones. Two layers (wide display boxes, narrow kill zones), consistent. Only BabyPips differs. Keep ONE shared table in code.
4. **Oscillators.** Images 6-7 and the "fused oscillator" of images 2 / 4 / 5 (levels 18 / 82 / 83) are older than the v7 oscillator. The embedded snapshot dashboard may still draw an older oscillator pane: to verify by opening it; if so label it "older snapshot".
5. **School voting (METHOD PROBLEM).** "Confirm 5 / Against 9" and "min 6 of 21 to confirm" are counts, not evidence: the schools are not independent (SMC / ICT / CRT-CISD overlap; MAs / Ichimoku / Momentum / VWAP / Pivots are all price-trend functions), so confluence is inflated; the threshold 6 of 21 has no test behind it; 4 of the 21 are n/a.
6. **Instrument mismatch.** CFX research = yfinance GC=F futures (delayed); live V7 = Hyperliquid xyz GOLD perpetual. Statistics from one do not transfer to the other.
7. **Signal direction.** The only measured oscillator rule (variant B) was 59.7 % AGAINST the next 8 bars (n = 62, not significant). Drawing BUY / SELL dots from it, or alerts "صفقة شراء / بيع", presents an untested rule as a trade call.

## 4. "Best trades and win rate": what the evidence allows
- Pipeline backtest on GC=F: n = 83, 37.35 % reached TP1 or better, +0.238 R after a $0.30 spread. n < 100 and no t-test passed: **not an edge**.
- Oscillator variant B: not significant either way. Chosen after trying three variants on the same sample (selection bias).
- Nothing in the images or the plan can honestly promise a win rate. What can be done is to MEASURE which tools add value:
  1. Freeze each tool's definition (one file per tool, tested).
  2. Backtest on a long history (not only Sep-Nov, 4525 bars) with costs, on the instrument we will trade, pre-registered in `docs/PREREG_*.md`.
  3. Ablation: setup with and without each tool / school; keep a tool only if expectancy (R) improves out of sample and n >= 100.
  4. Compare against a random-direction baseline (the lab already does this).
  5. Only then show win rate, expectancy and drawdown next to a setup; until then label every setup "research".
