## Side finding: `htf` (trading WITH the 100-bar trend) is not simply "worse"
The pooled number (-0.030R, t -6.39, n 36,512) hides opposite behaviour per timeframe (`*ALL*` rows, run 2): with-trend is bad on **1h** (-0.094R, t -5.84) and
**1m** (-0.031R, t -4.18), neutral on 15m/4h, while **against-trend is the bad side on 4h** (-0.046R, t -4.45) and good on 1d (+0.132R, t 1.9, IS -0.061 / OOS +0.213).
A rule that flips sign by timeframe looks like noise or regime drift, not a stable effect: **nothing is wired to it**, and the earlier line "with-trend is robustly
worse than random" in `docs/PIPELINE.md` is too strong; read this paragraph instead. Not tested: whether the 1.5 ATR stop / 1.5R target drives it (needs a lab variant).

Read with care: (1) the 12 exits use the SAME entries, so their agreement is not 12 independent confirmations; (2) gross R, before the 0.10R cost - most cells are negative after cost (exceptions: trail_only on 1m / 15m / 1h, against-trend on 1d); (3) **1m flipped sign since run 2** (2026-11-01: with-trend -0.031R, t -4.18; now +0.074R): 1m covers only the latest days, so that effect is not stable in time; (4) whole sample, no IS / OOS split in these rows, many cells tested at once. Conclusion: the timeframe dependence is real in this sample but not stable enough to use. **Nothing wired to the scanner.** The 1d against-trend line (+0.165R gross, t 5.45 at rr1.5) is the strongest cell; it would need its own pre-registration on future candles before any use.
