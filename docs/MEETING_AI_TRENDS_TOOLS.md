# محضر — ترندات وأدوات التداول بالذكاء الاصطناعي (2025–2026)

**الحالة:** مفتوح للعمل — مادة مرجعية كاملة للفريق  
**التاريخ:** 2026-10-23  
**النطاق:** ترندات السوق العامة والأدوات والتحليل (منفصل عن منطق أكاديمية المشروع الداخلي ما لم يُدمج لاحقاً بأمر صريح)

---

## [أمر المالك]

المحتوى المسجّل في هذا المحضر — كل الترندات والأدوات والشروحات والإيجابيات والسلبيات وتحليل الباك تست وما يُقال على السوشيال — **مطلوب العمل عليه**: فهمه، مناقشته، واستخراج ما يصلح للتبنّي أو التجربة أو الرفض بوعي. ابدأوا الشغل من هنا كمادة كاملة.

---

## 1) الهدف من المحضر

توحيد صورة واضحة عن:

1. ماذا يحدث في السوق الآن (ترندات).  
2. أنواع الأدوات وكيف تعمل.  
3. إيجابيات / سلبيات كل نوع.  
4. ماذا يقول القياس الجاد (باك تست / لايف / أبحاث).  
5. ماذا يقول السوشيال (X وغيره) — ضجيج مقابل إشارة.  
6. ترتيب عملي من الأكثر انضباطاً إلى الأكثر ضجيجاً.  
7. مهام مقترحة للفريق بعد القراءة.

---

## 2) الصورة الكبيرة

الانتقال الجاري:

| من | إلى |
|----|-----|
| بوت إشارة / Grid / DCA فقط | **Agentic trading** — وكيل يبحث ويخطط وأحياناً ينفّذ |
| «مؤشر + تنبيه» | حسابات بروكر للوكلاء + MCP/Skills + حوكمة |
| وعد تسويقي «AI يربح لوحده» | واقع القياس: بناء سهل · حافة صعبة · تكرار ضعيف |

**جملة محورية للفريق:** الأتمتة تنفّذ edge موجود؛ نادراً ما تخلق edge من اسم «AI» وحده.

## 3) خريطة أنواع الأدوات

| # | النوع | الفكرة | أمثلة تُذكر في السوق |
|---|--------|--------|----------------------|
| A | بوت قواعد كلاسيكي | شروط ثابتة: Grid، DCA، متوسطات | 3Commas، Pionex، Freqtrade |
| B | منصة استراتيجيات قابلة للأتمتة | بناء قواعد (أحياناً بلغة طبيعية) → باك تست → تشغيل | Composer by SoFi |
| C | وكيل على البروكر (Agentic) | موديل يتصل بالحساب عبر MCP وينفّذ ضمن حدود | Robinhood، Coinbase for Agents، Public، Gemini، IBKR، Webull، eToro |
| D | Multi-agent desk | أدوار: محلل، ريسك، منفّذ، مدقّق | TradingAgents وأطر مشابهة |
| E | بطاقة إشارة + تنفيذ | خطة كاملة → زر Execute | منصات كريبتو/perps شائعة على X |
| F | AgentFi / on-chain | وكيل على محفظة، perps، prediction markets | مشاريع AgentFi، محافظ وكيلية |
| G | بنية مفتوحة (محرك + بيانات) | أدوات تبني عليها لا «استراتيجية جاهزة» | NautilusTrader، OpenBB، Freqtrade |

> فيديوهات السوشيال غالباً تمزج A+E أو C وتسمّي الكل «AI يربح».

## 4) كيف تشتغل كل فئة (آلية)

### 4.1 بوت القواعد (A)

```
سعر / مؤشر → شرط مبرمج → أمر
```

- لا «فهم» سوق؛ تنفيذ رخيص وسريع.  
- الربح من جودة القاعدة + ملاءمة نظام السوق (ترند / نطاق).

### 4.2 منصة قواعد + AI يبني (B)

```
لغة طبيعية أو واجهة → قواعد صريحة (لو… إذن…) → محاكاة تاريخية → إعادة توازن آلية
```

- الـ AI غالباً **يبني** الاستراتيجية.  
- التنفيذ **محدد مسبقاً** — ليس قرار LLM كل ثانية.  
- Composer/SoFi يسوقون هذا التمييز بوضوح نسبياً.

### 4.3 وكيل البروكر (C)

```
موديل ← أدوات حساب/سوق (MCP) → اقتراح أو أمر
```

الخط الفاصل:

| نمط | المعنى |
|-----|--------|
| موافقة كل صفقة | كوبايلوت |
| تنفيذ ضمن سقف بلا موافقة لكل أمر | أوتونومي محدود |

### 4.4 Multi-agent (D)

```
بحث → أطروحة → اعتراض ريسك → [مدقّق أرقام] → تنفيذ أو رفض
```

- المبدأ القوي: من يريد الصفقة لا يصحّح لنفسه.  
- يرفع جودة الحوكمة أكثر مما يضمن alpha.

### 4.5 بطاقة إشارة (E)

```
مسح → بطاقة (اتجاه، دخول، وقف، أهداف، سبب) → تنفيذ محفظة
```

- UX ممتاز؛ إثبات edge مستقل صعب.

### 4.6 AgentFi / on-chain (F)

```
صلاحيات محفظة + استراتيجية على سلسلة → تنفيذ 24/7
```

- مخاطر أمنية أعلى (مفاتيح، حدود، تصيّد موجّه للوكلاء).

### 4.7 بنية مفتوحة (G)

- محرك تنفيذ موحّد باك تست/لايف، بيانات، بوتات.  
- أنت تملك السيرفر والمفاتيح وقرار الـ edge.

---

## 5) ترندات الفترة الأخيرة (ملخّص تنفيذي)

1. **حسابات وكيلية عند بروكرز منظّمين** — تقليل حاجز الدخول لملايين المستخدمين.  
2. **MCP / Skills** — طبقة توصيل للموديلات العامة بحسابات التداول.  
3. **التمييز بوت vs وكيل** — كثير من «AI bots» ما زالت قواعد + واجهة شات.  
4. **مكاتب multi-agent** — على GitHub وX كمعمار شائع.  
5. **Open-source stacks** — بنية بلا ترخيص؛ الربح غير مضمون.  
6. **Prompt → تنفيذ** (خصوصاً ميمز/perps) — قصص أرباح غير قابلة للتحقق غالباً.  
7. **حوكمة: kill switch، سقف، موافقة** — محور المؤسسات والجادّين.  
8. **AgentFi** — نمو واهتمام؛ نضج متفاوت.

## 6) إيجابيات وسلبيات حسب النوع

| النوع | إيجابيات | سلبيات |
|--------|-----------|---------|
| A قواعد / Grid-DCA | مفهوم، رخيص، قابل للباك تست، مستقر هندسياً | ينهار خارج نظام التصميم؛ ليس ذكياً |
| B قواعد + AI يبني | شفافية القواعد؛ اختبار قبل التشغيل؛ أقل هلوسة من وكيل حر | باك تست مجتمعي مبالغ أحياناً؛ DD كبير مع رافعة |
| C وكيل بروكر | راحة، لغة طبيعية، تكامل رسمي | تكلفة API؛ قرارات غير متسقة؛ صلاحيات خطر؛ أداء حي ضعيف في دراسات عامة |
| D Multi-agent | فصل أدوار؛ تدقيق؛ أقرب لمكتب | تكلفة وتعقيد؛ أخطاء مترابطة أحياناً |
| E بطاقة إشارة | UX وخطة كاملة | حافز تسويق؛ انحياز اللقطات؛ edge مجهول |
| F AgentFi | 24/7 وcomposability | أمان، سيولة، عمر استراتيجية قصير |
| G مفتوح المصدر | تحكم وتدقيق كود | مسؤولية التشغيل والمفاتيح والـ edge عليك |

## 7) باك تست · لايف · أبحاث (ما يجب أن يعرفه الفريق)

### 7.1 نتائج متكررة في القياس الجاد

| نوع الدليل | الخلاصة للتسجيل |
|------------|------------------|
| مواسم موحّدة لعشرات موديلات LLM (آلاف صفقات ورقية) | أقل من نصف المواسم تنتهي بربح؛ ترتيب موسم لا يتنبأ بالموسم التالي بثبات |
| أبحاث autonomous agents / LiveTradeBench | ذكاء عام ≠ قدرة تداول؛ إدارة مخاطرة ضعيفة كثيراً |
| معايير كريبتو (باك تست → paper → live) | فجوة كبيرة؛ عائلات LLM/agents غالباً أسوأ عند الاقتراب من التنفيذ الحقيقي؛ زمن قرار أبطأ |
| Postmortems عملية | البناء سهل؛ الحافة صعبة؛ فاتورة API حقيقية؛ باجز تنفيذ مكلفة |
| لوحات شفافة | متوسطات تحت السوق شائعة؛ الناشر الجاد ينشر الأرقام السيئة |

### 7.2 باك تست منصات الاستراتيجيات (مثل كتالوجات Composer)

- أرقام سنوية وSharpe مرتفعة تظهر كثيراً.  
- مخاطر معروفة: رافعة (مثال TQQQ)، فترات محظوظة، overfitting، رسوم/انزلاق المحاكاة ≠ اللايف.  
- التمييز المهم: **قواعد واضحة قابلة للمراجعة** أفضل من وعد «الموديل أذكى من السوق».

### 7.3 لماذا يموت الباك تست على اللايف

1. رسوم وانزلاق  
2. نافذة قصيرة / نظام سوق واحد  
3. رافعة  
4. زمن قرار LLM  
5. تغيّر النظام بعد النشر

## 8) السوشيال ميديا (X وغيره) — قراءة الفريق

| الصوت | الرسالة | كيف نتعامل |
|--------|---------|------------|
| إعلانات وإشارات | أرقام خيالية، بطاقة، نفّذ | لا تُعتمد كدليل |
| بناة أدوات | معماريات (اتنين AI، مهندس + قارئ سوق) | خذ الفكرة؛ اطلب قياساً |
| المعسكر الحذر | مدقّق قبل الأمر؛ paper أولاً | يتوافق مع الأدلة |
| قوائم GitHub | محركات وبيانات | بنية لا ضمان ربح |
| الأمن | حدود إنفاق، whitelist | إلزامي قبل أي وكيل حي |

**قاعدة المحضر:** اتفرج على المعمارية؛ لا تشتري رقم الكابشن.

## 9) أين يمكن أن تكون الحافة — وأين لا

| ادّعاء شائع | موقف المحضر بعد التدقيق |
|-------------|---------------------------|
| AI أذكى من المتداول فيدخل ربحاً ثابتاً | غير مدعوم كقاعدة عامة من القياس الحي |
| الأتمتة وحدها تربح | الأتمتة تنفّذ edge؛ لا تخلقه من الفراغ |
| Multi-agent يحل الربح | يحسّن الحوكمة؛ لا يضمن alpha |
| الباك تست يكفي | اللايف والـ paper الجاد هما الامتحان |
| وكلاء البروكر = المستقبل | صحيح كمنتج وUX؛ الـ P&L منفصل |
| الاستدامة | أقربها تاريخياً: قواعد بسيطة + مخاطرة + نظام مناسب؛ AI مساعد بناء/مراقبة |

## 10) ترتيب عملي (من الأكثر انضباطاً → الأكثر ضجيجاً)

1. محرك قواعد + باك تست جاد + paper + حدود صارمة  
2. AI يكتب القواعد → موافقة بشرية → تشغيل آلي للقواعد  
3. كوبايلوت بروكر بموافقة كل صفقة  
4. Multi-agent مع بوابة ريسك + مدقّق  
5. وكيل شبه مستقل بسقف وkill switch  
6. بطاقة إشارة / بوت تليجرام / قصة أسبوع على X  

---

## 11) أنواع «ما يبنيه الناس» في الفيديوهات (لتصنيف أي أداة جديدة)

عند ظهور أداة أو فيديو جديد، صنّفوه في دقيقة:

- [ ] بوت قواعد + شات يشرح  
- [ ] وكيل API بحدود  
- [ ] جمع بيانات → اقتراح → تنفيذ يدوي/شبه آلي  
- [ ] Multi-agent ديمو + بوابات ريسك حقيقية أو لا  
- [ ] بطاقة إشارة تسويقية فقط  

ثم اسألوا: أين القياس؟ أين الـ kill switch؟ من يمسك المفاتيح؟

## 12) مهام مقترحة للفريق (بعد أمر المالك)

| # | مهمة | مخرج متوقع |
|---|------|-------------|
| M1 | قراءة المحضر كامل وتعليق كل حساب (موافقة / تحفظ / سؤال) | تعليقات أسفل الملف |
| M2 | اختيار **فئة واحدة** للتعمق التجريبي أولاً (مثلاً: قواعد+باك تست، أو كوبايلوت فقط) | قرار مكتوب في التعليقات |
| M3 | جدول مقارنة لأي أداة مرشّحة: نوع A–G، موافقة بشرية؟، قياس؟، أمان مفاتيح؟ | جدول في تعليق أو ملحق |
| M4 | قائمة رفض صريحة (ما لن نلمسه الآن: إشارات تليجرام العمياء، وكيل بلا سقف، …) | قائمة |
| M5 | إن لزم لاحقاً: ربط انتقائي مع أدوات المشروع — **فقط بأمر مالك جديد** | لا يُفترض الدمج من هذا المحضر وحده |

## 13) مبادئ عمل مستخرجة من المادة (للالتزام أثناء الشغل)

1. أقل ضجيج تنبيهات / إشارات أفضل من الأكثر.  
2. قواعد قابلة للمراجعة أفضل من قرار صندوق أسود غير مقيس.  
3. Paper وقياس موحّد قبل فلوس حقيقية.  
4. فصل من يقترح عمّن يوافق على التنفيذ.  
5. Kill switch وسقف صفقة/يوم غير قابل للتفاوض قبل أي وكيل حي.  
6. السوشيال مصدر أفكار لا مصدر عوائد.

---

## 14) مراجع سريعة (أنواع مصادر — للتتبع لا للنسخ الأعمى)

- تقارير AgentFi / وكلاء البروكرز (Cambrian وأشباهها)  
- مقارنات MCP ووكلاء البروكر (Circuit، Hands Off، Turnkey harness notes)  
- معايير وأبحاث live/paper للـ LLM traders (TradeRank-style، AI-Trader، LiveTradeBench، معايير كريبتو متعددة المراحل)  
- Postmortems بناء بوتات LLM  
- كتالوجات استراتيجيات قواعد (Composer وغيرها) مع الحذر من overfitting  
- نقاشات X: إشارات تسويقية مقابل معماريات (verifier، multi-agent، open-source stacks)
