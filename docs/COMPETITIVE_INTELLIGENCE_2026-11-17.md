## 1. الهدف

بناء منافس قوي لا يقوم على تقليد مؤشرات الشركات أو ادعاء الربحية، بل على منظومة مستقلة تجمع:
- بيانات سوق موثوقة مع مصدر وتوقيت وتغطية وحقوق استخدام واضحة.
- محرك مؤشرات واستراتيجيات متعدد المدارس والأسواق والفريمات.
- Order Flow وLiquidity مع Replay مطابق للحساب الحي.
- Backtesting واقعي وAnti-Repainting وWalk-forward وOut-of-sample.
- Scanner متعدد الأصول لاكتشاف الفرص وترتيبها وشرح أسبابها.
- وكلاء AI متخصصين مع مراجعة خصومية وبوابات مخاطر ثابتة.
- REST/WebSocket API وSDK وWebhooks وMCP.
- أمن وخصوصية وسجل تدقيق وتطوير مستدام.
- تعليم ومجتمع وتقارير قابلة لإعادة الإنتاج.
- تكلفة تشغيل واضحة ومقاسة لكل مستخدم وتحليل ومصدر بيانات.

## 2. المنهجية وحدود الدليل

تمت مراجعة 15 اسمًا عبر صفحات المنتجات والتوثيق والأسعار والشروط القانونية ومستودعات GitHub ومراجعات العملاء حيث توفرت. أُعطيت الأولوية للمصادر الرسمية. مراجعات العملاء تصف تجربة الاستخدام ولا تثبت الأداء. الأسعار لقطة وقت الفحص وقد تختلف حسب البلد والضريبة والعرض والفترة. «غير موثق» تعني أن المصدر الذي تمت مراجعته لم يثبت المعلومة.

**قيد جوهري:** لم يقدم أي مصدر جُمِع دليلًا مستقلًا قابلًا لإعادة الإنتاج يثبت ربحية أو دقة إشارات أي منتج من المنتجات الـ15. لم يتم شراء اشتراكات أو تنفيذ اختبارات حية أو إرسال أوامر تداول. لا يجوز تحويل Backtests أو شهادات العملاء أو ادعاءات Non-Repaint إلى حقيقة مثبتة دون اختبار مستقل.

## 3. خريطة المنافسين

1. مؤشرات واستراتيجيات: LuxAlgo، ChartPrime، AlgoAlpha، Zeiierman، BigBeluga، FluxCharts.
2. منصات الرسوم والتحليل: TrendSpider، TradingView.
3. الماسحات والبحث: Trade Ideas، Trendlyne.
4. Order Flow وTrading Terminals: Bookmap، Quantower، ATAS، MotiveWave، GoCharting.

## 6. نقاط الضعف السوقية التي يمكن استغلالها

1. **غياب الدليل القابل لإعادة الإنتاج:** كثير من المنتجات تعرض نتائج Backtest أو شهادات دون بروتوكول مستقل. نكسب الثقة بنشر البيانات والإعدادات والكود ونتائج OOS.
2. **التبعية لمضيف أو مزود واحد:** نبني مصادر وواجهات قابلة للتبديل ونستعمل TradingView كتكامل اختياري.
3. **تشتت الأدوات:** نجمع التحليل الفني والسيولة والـOrder Flow والـScanner والـRisk في Workbench واحد دون تكرار.
4. **غموض Repainting:** نعرض حالة الإشارة: provisional/confirmed/invalidated مع توقيت التأكيد وسبب التغير.
5. **التكاليف الخفية:** نظهر تكلفة الترخيص والبيانات والبورصة والـAPI والانزلاق بصورة مفهومة.
6. **ضعف التفسير:** كل توصية يجب أن تعرض الأدلة المتعارضة والسيناريوهات والحدود، لا سهم شراء/بيع فقط.
7. **ضعف التحقق من الأتمتة:** نبدأ Read-only ثم Paper ثم Live approval، مع Kill Switch وسجل تدقيق.
8. **تجربة متخصصة منفصلة:** نربط Gann/SMC/ICT/Elliott/Harmonic/Price Action/Order Flow تحت نموذج موحد، دون ادعاء أن كل مدرسة تعمل في كل سوق.

## 7. خارطة بناء XPiX / AI Trading Dashboard

### المرحلة 0 — Trust & Validation Foundation
**المخرجات:** Event-sourced market-data/signal ledger؛ Anti-Repainting harness؛ Data lineage؛ سجل تراخيص؛ Threat model؛ Backtest benchmark واقعي.
**بوابة الخروج:** كل إشارة مؤرخة ومفسرة وقابلة لإعادة التشغيل؛ لا look-ahead أو repaint غير معلن؛ كل Backtest مربوط بنسخة بيانات وكود وإعدادات وتكاليف.

### المرحلة 1 — Multi-market MVP منخفض التكلفة
**المخرجات:** Charts + Scanner + Alerts + Research Notebook؛ بدء محدود بأسهم/ETF ومصدر Futures وبورصة Crypto واحدة؛ Order Flow حيث تسمح البيانات المرخصة؛ Read-only connectors وPaper Trading.
**بوابة الخروج:** صحة الموصلات والتأخير والفجوات ظاهرة؛ Live/Replay parity؛ توثيق تغطية وتكلفة كل سوق.

### المرحلة 2 — Automation & Extensibility
**المخرجات:** Broker adapters؛ مفاتيح أقل صلاحيات ومنع السحب؛ Signed/Idempotent Webhooks؛ Rate limits؛ Kill switch؛ حدود خسارة/تعرض؛ Immutable audit logs؛ REST/WebSocket SDK وStrategy schema.
**بوابة الخروج:** مصالحة Paper-to-live واختبارات فشل وأمان؛ كل أمر حي مرتبط بإصدار وموافقة مستخدم.

### المرحلة 3 — Multi-Agent Research & Education
**المخرجات:** Regime Agent؛ Technical Structure Agent؛ Order Flow Agent؛ Strategy Research Agent؛ Quant Validation Agent؛ Risk Agent؛ News/Event Agent؛ Adversarial Reviewer؛ Orchestrator يعرض اختلاف الآراء والمصادر.
**بوابة الخروج:** كل مخرجات الوكلاء لها provenance؛ لا نشر أداء دون بيانات وافتراضات وOOS؛ LLM لا يغير منطق التنفيذ بصمت.

### المرحلة 4 — Sustainable Scale
**المخرجات:** اتفاقات بيانات؛ تسعير حسب الاستخدام؛ Free/Research tiers؛ SDK ومكونات مفتوحة مختارة؛ مجتمع ودعم؛ Security policy؛ Incident response.
**بوابة الخروج:** اقتصاديات وحدة إيجابية؛ توافق API؛ Benchmarks عامة قابلة لإعادة الإنتاج؛ لا دعم خفي لتكاليف البيانات.

## 9. مؤشرات النجاح

**البيانات:** freshness، p50/p95 latency، missing-bar/gap rate، connector uptime، coverage، cost per source.
**الإشارات:** confirmation delay، invalidated/repaint rate، precision/recall وفق تعريف ثابت، MFE/MAE، net expectancy بعد التكاليف، OOS degradation، الأداء حسب regime.
**المنتج:** وقت الوصول لأول إشارة مفيدة، المستخدمون النشطون، alert latency، reproducibility rate، support resolution.
**الأمن:** incidents، secret exposure (الهدف صفر)، failed-order/reconciliation mismatch، recovery time، cost per active user.
لا نستخدم Win Rate وحده ولا نعد المستخدم بالربح.
