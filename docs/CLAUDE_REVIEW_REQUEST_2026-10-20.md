## المطلوب من Claude
1. اقرأ وثيقة `OWNER_REQUIREMENTS_2026-10-20.md` كاملة، وراجع `MEETING_ROOM.md` و`WHITEBOARD.md` قبل التعليق.
2. أكّد فهم نطاق التبويبات:
   - `Radar`: التبويب المستقل الكبير الذي يعرض 10 شارتات.
   - `Scanner`: الاسم يبقى كما هو داخل `Workspace`.
   - `Technical Office`: الاسم الجديد لتبويب `Lab`.
3. راجع متطلبات Radar، خصوصًا اختيار الفريم لكل شارت، إظهار الـPatterns وEMA Golden Cross عند تحقق شروطها، اختيار أفضل Setup لكل رمز، تحليل Elliott/Gann والمستويات الأعلى، ودمج Order Book فقط إذا كانت بياناته متاحة فعلًا.
4. راجع بقية الطلبات الموثقة، بما فيها التحكم في أعمدة الجداول، مظهر وحجم Order Flow/Bubbles، تحديث Social News/Street News عند اختيار اللغة، وملخصات الفلاتر الفنية.
5. أرسل ردًا واضحًا في محضر المشروع أو تعليق GitHub متاح، موجّهًا للمالك، يوضح:
   - ما الذي فهمته من الطلبات وما هو نطاق كل ميزة.
   - التعارضات أو الأسئلة التي تحتاج قرار المالك، إن وجدت.
   - المخاطر التقنية ومصادر البيانات المطلوبة، خاصة Level 2/Order Book والأخبار.
   - ترتيب تنفيذ مقترح على مراحل، مع معايير قبول قابلة للاختبار.
   - ما يمكن تنفيذه محليًا دون API مدفوع، وما يتطلب مزود بيانات أو تكلفة.
   - خطة اختبار تمنع repainting/future leakage وتفرّق بين الاحتمال الإحصائي والضمان.
6. لا تدّعِ أن أي ميزة نُفذت أو اختُبرت ما لم توجد أدلة قابلة للتحقق. لا تضع أسرارًا أو مفاتيح API في المستودع.
7. لا تعدّل كود التطبيق ولا تشغّل workflows مكلفة ولا تدمج أي شيء في `main`. إن اقترحت تعديلات، اعرضها أولًا في تقرير منفصل واذكر الملفات المتأثرة.
