## 1. القواعد اللي مفيش فيها نقاش
1. **المنصة ماتقفش، ونسخة واحدة بس.** التقسيم بيحصل في مكانه على مراحل صغيرة (§3.4)؛ التغيير الكبير بيبقى ورا مفتاح تشغيل لحد ما يتأكد. مفيش وظيفتين بيعملوا نفس الحاجة.
2. **قياس قبل وبعد.** مفيش "اتصلح" أو "أسرع" من غير رقمين. مفيش كاش عشوائي، ولا تقليل حداثة بيانات السوق من غير قياس.
3. **مفيش حذف أو دمج أو تغيير ترتيب لأي صفحة/تاب/وظيفة** من غير موافقة جديدة من المالك (نفس قاعدة 2026-11-09).
4. **النتايج ماتتغيرش:** الإشارات، الماسح، الجورنال، الباك تيست لازم يطلعوا نفس الأرقام. أي نقل لكود حسابي ييجي معاه اختبار مقارنة (parity).
5. **الشارت:** عدّل `modules/ws/*` وابنِ بـ`python3 scripts/build_workspace.py`، مش `workspace_app.html` المولّد.
6. **الأسرار** في Streamlit Secrets / env بس. البيانات الشخصية (`data/journal/`، `data/spot/`) ماتتنقلش للـgit.
7. **ملف واحد = صاحب واحد في نفس الوقت.** شوف جدول الملكية (§8) عشان مفيش اتنين يعدّلوا نفس الملف.
8. اكتب "ماتجربش" بوضوح: السيرفر المنشور، جهاز المالك، البيانات الحية.

## 3. شكل النسخة الخفيفة (الهدف)
### 3.1 قاعدة "مفيش حاجة تشتغل لحد ما حد يستخدمها"
| الطبقة | دلوقتي | المطلوب |
|---|---|---|
| الصفحات | `if PAGE == N` جوه `main.py` | ملف لكل صفحة (`st.navigation` + `st.Page`)؛ الصفحة بتستورد اللي محتاجاه بس جوه الملف |
| التابات جوه الصفحة | معظمها اختيار واحد بالفعل، 2 `st.tabs` | اختيار (`st.segmented_control` / `st.radio`) وتشغيل التاب المختار بس |
| الاختيارات والأقسام التقيلة | بتتحسب مع الصفحة | تتحسب لما تتفتح (زرار/expander) جوه `st.fragment` |
| الأجزاء الحية | `st_autorefresh` بيعيد الصفحة كلها | `st.fragment(run_every=...)` على الجزء الحي بس |
| الحسابات | بعضها كل rerun | `st.cache_data` بـTTL واضح لكل مصدر |
| شغل الخلفية | خيوط جوه عملية الواجهة | worker منفصل (GitHub Actions مجدول أو عملية لوحدها) بيكتب snapshots؛ الواجهة **بتقرا بس** |

### 3.2 الشارت (Workspace)
- **ملفات ثابتة بكاش:** نقل JS/CSS لـ`static/` (`server.enableStaticServing = true`) بأسماء فيها رقم نسخة → المتصفح بيحمّلهم مرة واحدة. الـiframe يبقى صغير (هيكل + بيانات).
- **قلب صغير + أجزاء عند الطلب:** الشارت والواتش ليست في القلب؛ أدوات الرسم، اللوحات، المساعد، التصنيف، الأوردر فلو تتحمّل لما تتفتح (`import()` ديناميكي أو `<script>` بيتضاف وقت الطلب).
- **بيانات من غير إعادة تحميل:** الماسح/الأخبار توصل للشارت عن طريق جسر (component) بـ`postMessage` بدل ما نبني HTML جديد كل 3–10 د.
- **مدير بيانات واحد في المتصفح:** WebSocket واحد لكل مصدر (OKX / Hyperliquid / Finnhub) مشترك بين كل الشارتات بدل اتصال لكل شارت.
- **التوفير:** شارت مصغّر أو مخفي مابيتحدّثش؛ التاب لما يروح الخلفية (`visibilitychange`) التحديث يبطّأ لـ30 ث؛ مؤقت مركزي واحد بدل 32.
- **حد أقصى للحجم:** اختبار بيفشل لو القلب كبر عن الميزانية (مقترح: القلب ≤ 400 KB).

### 3.3 تقسيم الريبو (نسخة واحدة بتتبني في مكانها)
```
main.py                    # بيصغر تدريجيًا لحد ما يبقى st.navigation بس (مدخل Streamlit Cloud زي ما هو)
app/pages/                 # ملف لكل صفحة (workspace.py, radar.py, spot.py, tia.py, ...) — الصفحة بتتنقل من main.py هنا
app/ui/                    # عناصر واجهة مشتركة (header, status strip, css, i18n wrapper)
app/services/              # قراءة الـsnapshots + الكاش (ممنوع أي شغل خلفية هنا)
core/                      # منطق حسابي صافي من غير streamlit (signals, scorer, regime, journal, spot_core...)
workers/                   # شغل الخلفية: scan, smt, dayplan, feeds → بيكتب في data/snapshots/
web/workspace/src/         # أجزاء الشارت (من modules/ws/*) مقسمة core + chunks
static/ws/                 # ناتج البناء بأرقام نسخة (يتولّد، ماتتعدلش يدويًا)
tests/                     # نفس الاختبارات + parity قبل/بعد كل نقلة
```
- `core/` **ماينفعش** يستورد `streamlit`. ده اللي بيخلي الحسابات تتختبر وتشتغل في الـworker والواجهة بنفس الكود.
- **النقل:** الكود بيتنقل (`git mv` + تعديل الـimports)، **مش بيتنسخ**. لو حاجة لسه بتستورد من المكان القديم، يفضل فيه سطر re-export مؤقت (`from core.signals import *`) لحد ما كل المستوردين يتحدّثوا، وبعدها يتشال.

### 3.4 قرار المالك (2026-11-25): نفس الريبو، نسخة واحدة
- **نفس الريبو.** مفيش ريبو جديد، ومفيش تطبيق تاني جنب الأولاني.
- **نسخة واحدة بتتبني في مكانها:** كل مرحلة صغيرة بتحوّل جزء من القديم للشكل الجديد، والمنصة شغالة طول الوقت على نفس الرابط. مفيش `app_v2.py`.
- **الأمان بدل النسختين:** كل نقلة في PR صغير لوحده + parity + AppTest؛ والحاجات الكبيرة (زي الشارت الخفيف) ورا مفتاح (مثلًا `WS_LITE=1`) لحد ما تتأكد، وبعدها المفتاح يتشال.
- **الكود القديم اللي اتنقل منه:** بيتشال في نفس الـPR بعد ما المستوردين يتحدّثوا. اللي يفضل من القديم في الآخر، المالك يقرر يعمل فيه إيه.
- **ممنوع:** وظيفتين بيعملوا نفس الحاجة (قديمة وجديدة) يفضلوا شغالين مع بعض بعد ما الـPR يتدمج.

### 10.2 التوصية
1. **الواجهة:** تفضل على Streamlit Cloud (زي ما المالك قال)، بس **تقرا بس** (snapshots) — مفيش ماسح ولا خيوط تقيلة جواها (المرحلة 3).
2. **الخلفية كلها على Oracle Always Free VM واحدة:** `workers/` (scan / smt / dayplan / feeds) + البوتات + cron بـ`systemd timers`. بتكتب الـsnapshots في git branch خاص (زي `bot-state`) أو R2، والواجهة بتقراها.
3. **Cloudflare Workers:** الـwebhooks والمواعيد الدقيقة (بدل جدول GitHub المتأخر) ويصحّي الـVM أو الـworkflow.
4. **GitHub Actions:** للشغل الأسبوعي التقيل بس (باك تيست، أبحاث) زي ما هو.
5. **لو Oracle مارضيش يدّي A1:** البديل نرجّع الخلفية لـGitHub Actions + Cloudflare Worker يشغّلها في الميعاد، ونقبل إن البوتات تبقى أبطأ. أي حل مدفوع رخيص (VPS بـ~4–5$/شهر) قرار المالك.
- **على المالك:** يعمل حساب Oracle Cloud (Home region أمريكي زي Ashburn/Phoenix عشان التوفر — مايتغيرش بعد كده) ويقول. **ماتبعتش أي مفاتيح في الشات**؛ بتتحط في الـsecrets بس.
