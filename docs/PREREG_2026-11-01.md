# Pre-registration - two hypotheses, frozen 2026-11-01 (item 25)

**Why:** both were picked as the best-looking rows of a lab run with ~1,257 rows (built 2026-11-01 05:05 UTC), so that run's numbers are biased upward
(winner's curse). The only honest check is signals that did not exist when they were picked.

| | hypothesis | picked from run 2 (biased) |
|---|---|---|
| H1 | detector `sess_amd` AND chain layer `loc` (long in the lower third / short in the upper third of the 50-bar range) | n 157, +0.187R gross, +0.087R net, IS +0.231 / OOS +0.140 |
| H2 | detector `ohl_open` in the 20-24 UTC session (`ses == "Late 20-24"`) | n 437, +0.196R gross, t 3.83, IS +0.176 / OOS +0.205 |

**Frozen (not to be tuned on this data):** the lab's procedure as is - stride 4, cooldown, stop 1.5 ATR, target 1.5R, per-timeframe horizon, 12 symbols x
5 timeframes, random-direction baseline per signal, cost 0.10R per trade (`COST_R`).

**Counted data:** only signals whose bar time is **after 2026-11-01 05:05 UTC** (`PREREG_CUTOFF_MS` in `modules/strategy_lab.py`; every event now carries `ts`).
The weekly lab writes two `*PREREG*` rows into `data/strategy_lab.json` and a "Pre-registered tests" section into the report.

**Pass gate (both must hold):** n >= 100, t vs random direction > 3, net avg R > 0 overall AND in both time halves (split at the median signal time).
Two hypotheses only, so no multiple-testing correction beyond that. **Under n = 100 it is not evidence, whatever the numbers say.**

**Decision rule (set now):** pass -> the setup may be proposed to the scanner as a *rank bonus* (never a hard filter), with the number shown honestly as
"after-cost, out-of-sample"; fail after n >= 100 -> closed as not evidence, not re-tuned and not re-run on the same data; n < 100 -> wait.
Expected time to n >= 100: unknown (H1 had n 157 in ~1,500 bars per series; fresh data arrives one bar at a time), so check the weekly row, do not guess.

## Side finding: `htf` (trading WITH the 100-bar trend) is not simply "worse"
The pooled number (-0.030R, t -6.39, n 36,512) hides opposite behaviour per timeframe (`*ALL*` rows, run 2): with-trend is bad on **1h** (-0.094R, t -5.84) and
**1m** (-0.031R, t -4.18), neutral on 15m/4h, while **against-trend is the bad side on 4h** (-0.046R, t -4.45) and good on 1d (+0.132R, t 1.9, IS -0.061 / OOS +0.213).
A rule that flips sign by timeframe looks like noise or regime drift, not a stable effect: **nothing is wired to it**, and the earlier line "with-trend is robustly
worse than random" in `docs/PIPELINE.md` is too strong; read this paragraph instead. Not tested: whether the 1.5 ATR stop / 1.5R target drives it (needs a lab variant).
